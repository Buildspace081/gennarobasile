## Problem

Many RAG demos stop when a model returns a plausible answer. This project asks a harder question: how can retrieval quality, grounding and failure modes be made visible enough to improve the system?

## Why I am building it

Text Mining introduced the components. Building the pipeline makes their interactions concrete: chunking affects recall, retrieval affects context, and evaluation changes what “working” means.

## What I am building

The first iteration will include a small documented corpus, a reproducible ingestion pipeline, inspectable retrieval results and an evaluation notebook. This page intentionally describes work in progress; no final metrics are claimed yet.

## Planned architecture

`documents → chunking → embeddings → vector index → retrieval → prompt context → answer → evaluation`

## Current status

Scoping the corpus and defining a baseline evaluation set. Repository and results will be linked when they are ready.

## What I expect to learn

- How chunk size and overlap influence retrieval.
- Where semantic similarity produces convincing but irrelevant context.
- How to separate retrieval errors from generation errors.
